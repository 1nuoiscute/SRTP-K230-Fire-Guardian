## 电脑端开发候选

以 [演示范围](DEMO_SCOPE.md) 为依据，优先检查锅下及无遮挡蓝焰的实际定位、连续视频中的火焰漏检和框稳定性，以及关火、锅内食物、普通烹饪羽流的误检。贴纸抑制仍为可选鲁棒性，不单独否决无贴纸演示候选。正常灶火检测是视觉证据，不能直接当异常火灾报警。

采用判断记录以下几项并说明取舍，不把它们合成无依据的单一分数：

1. **项目收益：** 改善了哪个实际场景；锅下蓝焰、真实火焰框范围和连续定位优先于已曝光旧图排名。照片局部增益是进入视频复核的线索，还不能证明整个场景可靠。
2. **演示内代价：** 在同一完整画面、同一预处理和固定阈值下，检查无火、食物、烹饪羽流、熄火段和持续漏检。明确真实错误、定位口径差异与暂时无法判断的画面，不将不确定样本当正确。
3. **旧来源回归：** 继续报告原286图mAP、TP/FP/FN和综合F1，用于发现退化并解释风险。原灶火框常覆盖锅体，几何目标变化会影响AP；旧AP下降本身不自动否决正确火焰定位的新模型。水印、日落等演示外误检保留为推广边界，不隐去也不自动等价于演示失败。
4. **部署代价：** 参数、CPU入口、ONNX输出契约、预处理差异及以后板端后处理适配成本。电脑耗时不冒充K230或完整报警时延。保留旧模型和明确回退身份。

所有声明的best/last均可进入项目视频复核，不因历史回归门槛失败被提前排除。图片信号仅安排复核顺序；最终选择需有代表性完整视频与对应真值/目视检查支持，明确适用范围和已知问题。没有可核对的项目收益或仍存在未解释的演示内失败时，继续开发或保留当前候选，不能仅因训练结束就宣布采用。

当前从零训练v14的旧规则记录为“两份未通过”；按本次新标准，它们在蓝焰4/5上的收益值得检查实际视频，但19/18个旧无火误检和旧厨房46/57匹配仍是需要解释的代价。尚未完成项目视频复核，当前v13继续保留。这是用户修改判断原则后的重新评估，不将旧规则结果改写为已通过。
