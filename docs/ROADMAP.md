# 推进顺序与门槛

1. 代码、构建和板端产物身份固定；建立公开仓库、参考索引及自动检查。
2. 用经人工查看的蓝焰帧、贴纸难负例和旧数据保持样本开展 v5 对照。记录原视频、派生裁剪、标签、重复加权、初始化权重及哈希。
3. 比较 v3/v5 的旧视频回归、队友视频开发诊断、未训练的蓝焰照片与旧 286 图诊断。保留失败，若关键项倒退则拒绝替换候选。
4. 收集全新、按厨房/完整事件隔离的验收素材；它们在权重和阈值冻结后只运行一次。没有新增数据时继续开发能力，独立验收保持未完成。
5. 完成真实同步记录、烟雾输入、固定规则与自适应的事件级对照，再做模拟执行、断网/掉电和长时测试。
6. 电脑端候选经独立验证后才准备 ONNX/KModel 同图对照；待开发板开机后另做实机验收。

每轮候选只改变有记录的主要因素，不以反复调诊断集成绩为目标。公开说明必须区分：框检测、事件判断、执行反馈、实时运行。

照片按原作页、原始文件身份和人工场景组交叉审核：仅更换下载尺寸或编码不能成为新来源。v7 已把两个旧诊断原作转入训练，相关诊断必须按曝光范围分组；开发集上的回归不充当独立验收。

## 2026-09-30 用户调整的演示重点

贴纸误检不再是必须完成的修复目标，演示采用无此类贴纸干扰的灶台。后续优先实际蓝焰定位、连续识别，以及食物/蒸汽等演示内误检；不能仅因贴纸误检否决演示候选。正在运行的 v10 保持冻结数据和参数，既有结果如实保留。具体范围见 [演示范围](DEMO_SCOPE.md)。
