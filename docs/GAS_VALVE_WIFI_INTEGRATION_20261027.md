## 新增实现

- ADS1115 通过现有 GPIO I²C 总线读取单端输入：地址 `0x49`，AIN2 为 MQ-2，AIN1 为火焰模块，输出单位 mV。
- 采样程序显示六行环境/气体读数，补 OLED 小写字库；循环内显示刷新失败继续采样。首次 OLED 初始化失败仍会退出，ADC 两路同时失败后当前程序不再重试 ADC。
- `status_bridge.c` 追加 mq2/flame 生成 v2 状态；源读数超过 5 s 标记失效。状态每 0.5 s 写入，历史每 2 s 更新；面板兼容 v1/v2。
- D2/pad 63 驱动低电平触发继电器，方向寄存器改为读改写以保留其他位。阀门脚本包含开/关/读回及测试入口。
- `fire_guard.sh` 使用气体、火焰、绝对温度和温升判断；湿度、气压只显示；没有读取视觉检测框。
- WiFi 工具与 `S95srtp_wifi`、`S96srtp_fire_guard`、rootfs 启动器处理连接和启动顺序。
- `tools/rt_smart/` 提供 Zig 编译、LLD 链接的大核构建方法，路径仍以队友机器为默认，换机需修改。

## 默认阈值与恢复

| 输入 | 关阀条件 | 从关闭恢复时的条件 |
|---|---|---|
| MQ-2 | ≥650 mV | ≤490 mV |
| 火焰模块 | ≥1200 mV | ≤1000 mV |
| SHT31 温度 | ≥60℃ | <45℃ |
| 温升 | 约 30 s 上升 ≥8℃ | 温升 ≤2℃ |

实际判据以 `src/key_controls/fire_guard.sh` 和 `srtp_fireguard.conf` 为准。恢复是自动开阀，没有人工复位锁定；这些参数是台架原型阈值，尚未完成标准浓度或厨房事件标定。

## 队友报告的实机结果

以下数据来自 PR 描述和配置备注，未由本次整合重新采集：

- MQ-2 清洁空气基线约 418～450 mV；配置更具体记录 418～431 mV、均值约 422 mV。
- 打火机气体测试峰值约 1536～1544 mV；配置备注测试距离约 5 cm、读数约 45 s 衰减。
- 阀门开合正常，行程约 12 s，断电自关。
- 温度联动吹气约 3 s 触发；不据此推定默认温升条件已完成完整计时验收。
- WiFi 连接后可 ping 公网；未包含 MQTT 或远程告警验收。

## 尚待处理

1. 火焰模块没有可用火焰响应，阈值暂置于空载读数之上；需先确认模块、接法及响应方向。
2. 无数据保护只覆盖三路同时无效。MQ-2 单独失效但温度有效时仍可能开阀。守护未检查 seq 是否推进或状态文件是否冻结；桥接停止后旧的有效值可能继续被使用。
3. 守护进程退出不等于断电，当前 stop 分支没有显式关阀；没有阀门位置反馈，脚本状态不代表实际行程完成。继电器寄存器读改写也不等同于跨进程原子同步。
4. 大屏按 250～500 mV 映射相对百分比、OLED 在 500 mV 报警、控制在 650 mV 关阀，需统一配置与显示含义。
5. 视觉输出、正常灶火/异常事件判断、自适应标定、长时稳定和独立场景验收仍未完成。
6. 原 PR 漏将 `ads1115.c` 加入两个既有小核构建命令；本次整合补入 `src/sensor_mvp/build.sh` 和 `src/key_controls/build.sh`，避免新增驱动出现未定义符号。此修正没有改变控制策略。
