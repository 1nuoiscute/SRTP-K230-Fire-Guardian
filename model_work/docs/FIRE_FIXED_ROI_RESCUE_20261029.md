# 固定区域条件补检开发实验｜2026-10-29

## 结论和边界

原画面无框时才对固定宽区域做第二次模型推理，ROI 为画面横向10%–90%、纵向25%–90%，再把框映射回原坐标。这个区域根据已曝光的视频7选取，不是目标设备标定结果；已有全画面框时不触发，因此不处理原有大框和错误框。每帧最多两次模型推理，没有实测板端耗时。结果只用于开发诊断，不启用为默认策略，更不能直接作为火灾报警。火焰 v16 best 演示、v18 last 定位开发、v24 last 研究对照；烟雾旧双头 v4 和独立候选 v6 last 保留。

## 验证与局限

独立读取结果重算了1014帧、931帧和215图的数量、唯一身份、条件触发、补检框有限性和坐标范围、逐组统计和三个权重 SHA-256；核验215张图及空标签哈希。307个历史采样和视频7全734帧的像素哈希及三模型全画面预测逐项一致；视频1历史32帧同样复现。视频和图片复核页哈希均核对，摘要见 `docs/fire_fixed_roi_rescue_20261029.json`，本机完整记录在 `model_work/out/fixed_roi_*_20261029/`。

源码字节身份：本次运行时脚本在本机为 CRLF，仓库按 `.gitattributes` 保存为 LF；结果计划中的脚本 SHA-256 对应运行时原始字节，而不是 Git 规范化后的 blob。保留当前本机原脚本；跨环境复现须先核对字节哈希，不得把换行差异误认为算法变更。

代码边界：当前 `map_boxes` 容忍最多0.1像素越界后截断，若一个框完全处于裁剪边界外但仍在容差内，截断后可能退化为零面积框。实际保存的所有补检框已独立核验均为正面积且在ROI内，故此问题不改变本次计数；复用到生产或进一步实验前应修复并补充边界测试。不要修改历史输出以掩盖脚本身份差异。

这不是独立测试，也没有新增量化或K230上板证据；四张隔离预留源未使用。下一步应先明确真实固定机位、ROI外覆盖和机位移动策略，收集可区分正常烹饪与燃烧的跨事件真值，对背景误框和关火段做独立验证；不要用本段曝光视频调参后宣称泛化。
