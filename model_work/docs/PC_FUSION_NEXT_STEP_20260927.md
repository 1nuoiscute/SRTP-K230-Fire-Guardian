# 厨房火情视觉与传感器融合：电脑端下一步

状态：已有[电脑端概念稿和假数据回放](PC_FUSION_CONCEPT_AND_SIMULATION_20260927.md)；**未接真实烟雾数据、未校准、未独立验收**。回放只验证规则逻辑，不是报警能力成绩。

## 先把目标说准

第一阶段目标是“在限定厨房场景中区分正常灶火、可疑变化并给出可解释的预警记录”，不是凭一张火焰图判断火灾，也不是替代独立、合规的烟雾报警器。正常蓝焰应该被视觉模块找到，但不应仅因有 `fire` 框就触发危险报警。是否真的能减少误报、提前发现异常，要按完整事件测试。

## 现有输入与缺口

| 通道 | 现在有什么 | 对判断的作用与边界 |
|---|---|---|
| 视觉 | 电脑端 v3 候选，可输出 `fire` 框、置信度、位置与时间；仅在已训练的四段视频上表现稳定 | 可看火焰是否在灶头、是否扩大/移位；新厨房可靠性未验收 |
| 温湿度 | SHT31 曾在板端读数与 OLED 显示 | 记录环境变化；湿度有助于分析蒸汽，但不能用“湿度高”排除火灾 |
| 温度/气压 | BMP280 曾在板端读数与 OLED 显示 | 温度变化可作辅助；气压不是烟雾或可燃气体测量 |
| 烟雾 | 当前没有经过集成与记录的烟雾输入 | 需要有时间戳的真实连续读数及安装位置记录；不同烹饪活动也可能产生烟雾颗粒 |
| CO/可燃气体 | 当前没有 | CO、燃气泄漏与可见火焰是不同风险；如以后增加，应分通道和事件验收 |

## 我们按这个顺序做

1. **冻结视觉输入。** 暂用 v3 权重和固定阈值作电脑端候选，先保留每帧火焰框与时间戳。四段已训练视频只用于接口调试，不能当融合算法的独立成绩。
2. **做同步记录。** 新数据每行至少记录：`timestamp`、视频/厨房/机位/事件 ID、视觉框和置信度、SHT31 温湿度、BMP280 温度/气压、烟雾原始值、各通道是否有效、人工事件标签。所有通道使用同一时间基准；记录传感器安装位置和通风状态。
3. **先做透明规则，不先训练黑箱。** 状态分为“正常、关注、预警、报警”，另有“传感器故障/证据不足”。候选依据为火焰是否离开灶头、是否持续扩大，烟雾是否持续上升，温度是否相对本机位基线快速上升。单个短时尖峰先记录为关注；任何独立烟雾报警器本身的报警不得被视觉算法判成“正常”而压制。持续时间、变化率与阈值都待真实数据确定，现阶段不填想象数值。
4. **整段事件验收。** 正常做饭、蒸汽、反光、开关火、锅遮挡分别记录误报；异常场景只使用安全、可控且有明确真值的资料/实验，不在家庭厨房制造危险火情。报告逐事件漏报、误报、报警延迟、传感器失联时行为，并比较“仅视觉、仅烟雾、固定规则融合”。按厨房和完整事件隔离训练与测试，不把相邻帧当独立样本。

## 当前决策

**现在不继续用同一批图片刷视觉训练，也不凭现有 SHT31/BMP280 数据宣称准确预警。** 电脑端可以先准备同步数据格式与回放程序；能否定阈值和报告准确性，取决于新增烟雾连续数据和未见过的完整厨房事件。下一次拿到新数据后先做只读清点，冻结来源，再运行对照。

参考依据：NIST 的[烟雾与 CO 融合实验](https://www.nist.gov/publications/enhanced-residential-fire-detection-combining-smoke-and-co-sensors-sp-965)显示组合信号可改善实验中的干扰区分；其[厨房烹饪误报研究](https://www.nist.gov/publications/performance-new-smoke-alarms-and-aerosol-measurements-range-nuisance-cooking-sources)也表明烟雾信号本身会受正常烹饪影响。两者都不能代替本项目在实际机位的验证。
