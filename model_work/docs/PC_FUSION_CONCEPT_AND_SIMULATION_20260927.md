# 厨房视觉与传感器融合：电脑端概念稿和模拟

日期：2026-09-27。阶段：**概念验证，未接板、未接真实烟雾传感器、未校准、未验收**。

## 想解决什么

视觉模型负责说“哪里像火焰、框有多大、是否越出灶头”；传感器负责记录“烟雾和温度有没有相对本机位基线持续上升”。正常做饭本来就会有灶火，因此有火焰框本身不等于火灾。四段现有视频已参加视觉训练，只能用于开发接口，不能拿来估算新场景准确率。

```text
逐帧视觉框 + 固定灶头区域 ─┐
烟雾读数及有效标记 ─────────┼─> 同一时间轴 ─> 持续时间与多信号规则 ─> 状态 + 触发原因
温度基线差及有效标记 ───────┤
湿度变化（蒸汽提示） ───────┘
独立烟雾报警信号 ────────────────────────────────> 直接报警并锁定
```

每个机位要先人工画出灶头范围；锅具移动、相机移动后必须重新检查范围。烟雾和温度都需要安装位置、时间戳、健康状态与基线。湿度升高只提示“可能有蒸汽”，**不能抵消烟雾或火焰风险**。独立报警器触发时，融合规则不得覆盖它。

## 候选状态和规则

| 状态 | 在这版模拟里的含义 |
|---|---|
| 正常 `NORMAL` | 视觉、烟雾、温度数据都有效，且当前无异常；灶头范围内的正常火焰允许存在。 |
| 关注 `WATCH` | 一次或短时出现越出灶头的火焰、烟雾升高或温度升高；先留下记录。 |
| 预警 `WARNING` | 越界火焰持续，或高烟雾持续，或烟雾与温度同时升高并持续。短暂回落后保留一小段时间，避免状态反复跳动。 |
| 报警 `ALARM` | 越界火焰与高烟雾/高温同时持续，或高烟雾与高温同时持续；独立烟雾报警输入可直接触发。触发后锁定，风险消失且所有必要数据恢复才允许人工复位。 |
| 证据不足 `UNKNOWN` | 视觉、烟雾或温度缺失且没有已观察到的异常；不能显示成“安全”。若缺失时仍看见异常，继续显示关注/预警，并附带缺失原因。 |

这里的“持续”是抗单点噪声的设计想法，不代表已找到正确时长。气体泄漏、CO 和可见火焰属于不同危险，后续若增加气体传感器，应有单独的判断与真值数据，不能把所有读数揉成一个“火灾分数”。

## 电脑模拟做了什么

使用 [模拟输入](../data/fusion_demo_scenarios_20260927.csv)、[演示参数](../data/fusion_demo_config_20260927.json) 和 [离线回放程序](../src/fusion_replay.py)，按 1 秒间隔构造 5 段假想过程，共 24 个读数。烟雾指数是 **0–1 的虚构占位量**，温度是相对基线的虚构差值；参数文件中的 0.35、0.7、3°C、8°C、2 秒、4 秒等数值仅用于让状态机跑通，**不能用于实际厨房报警**。

| 假想过程 | 本次回放的关键结果 | 预期含义 |
|---|---|---|
| 正常做饭 | 始终正常 | 有灶火但没有异常，不因火焰框直接报警。 |
| 蒸汽/烹饪干扰 | 第 1 秒关注，第 3 秒恢复正常 | 湿度提示蒸汽，但未直接压掉烟雾变化。 |
| 火焰越界，后来烟温上升 | 第 1 秒关注，第 3 秒预警，第 8 秒报警；第 9 秒仍锁定，第 10 秒人工复位 | 状态按持续证据升级，报警不会随读数一回落就消失。 |
| 烟雾和温度数据缺失 | 证据不足；第 1 秒见越界火焰时关注 | 缺数不显示“正常”。 |
| 独立烟雾报警触发 | 立即报警；信号撤销后仍锁定，人工复位才回正常 | 视觉模块不能否决独立报警。 |

逐时刻输出见 [per_sample.csv](../out/fusion_demo_20260927/per_sample.csv)，状态变化及原因见 [transitions.csv](../out/fusion_demo_20260927/transitions.csv)，输入与参数 SHA-256 见 [summary.json](../out/fusion_demo_20260927/summary.json)。状态机的 11 项基础测试已通过，覆盖正常灶火、缺数、蒸汽提示、持续升级、锁定复位和时间断档。它们只证明**程序按设计工作**，不是识别准确率，也不是消防安全验证。

## 下一步需要什么，才能讨论“准确”

1. 等板端能稳定输出时间戳和传感器有效标记后，先记录**真实同步数据**；烟雾输入目前不存在，需另行选型、安装和测量。没有烟雾传感器时，只能检查视觉/温湿度接口，不能检验完整融合。
2. 收集完整且标注事件起止的正常做饭、蒸汽、反光、开关火、锅遮挡和安全可控的异常资料。按**厨房/机位/完整事件**隔离开发与测试。现有四段视频都已用于视觉训练，不是盲测。
3. 用开发集估计传感器基线、阈值和持续时间；冻结规则后，在新录、未参与任何调参的完整视频/同步读数上报告逐事件误报、漏报、报警延迟和断线行为。若没有异常事件真值，就不能报异常检出率。

当前结论：这个概念值得继续做，**但电脑模拟只能说明流程自洽，无法证明它能准确预报厨房火灾**。实际产品必须保留独立、合规的火灾报警保护；本规则目前只是研究原型。
